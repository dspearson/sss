# Release-Signing Public Keys

This directory holds the **public** keys for sss release-artefact
signing. Private keys are NEVER committed here — they live offline
on encrypted storage per the release-signing key policy
(`docs/RELEASE.md § Release-Signing Keypair`).

## File Layout

- `sss-release-sig-v<N>.pub` — Ed25519 public key for the fallback
  offline-signing flow. The comment header records the
  domain-separation tag (`sss-release-artifact-sig-v1`) and the
  generation timestamp. Generated by
  `scripts/release/generate-release-key.sh`.

## Why an offline fallback?

The PRIMARY signing path is sigstore/cosign keyless via GitHub Actions
OIDC (Phase 25 SIGN-02). The offline Ed25519 keypair is the FALLBACK
for:

- Verification in environments where sigstore is unavailable
  (air-gapped systems, offline reproducible-build verification).
- Cross-verification of cosign signatures (independent confirmation
  via a key the release operator holds end-to-end).

Per locked decision D-V23-04, the offline keypair is REGENERATED per
major version (v2.3 -> v3.0 etc.) so a compromise of the offline key
material has a bounded blast radius.

## Verification

Verify a release artefact with the offline public key:

```bash
openssl pkeyutl -verify \
    -pubin -inkey docs/release-keys/sss-release-sig-v1.pub \
    -sigfile sss-<cell>.tar.gz.offline.sig \
    -in sss-<cell>.tar.gz
```

The public-key fingerprint (SHA-256 of DER-encoded pubkey) is recorded
in `docs/RELEASE.md § Release-Signing Keypair`.

## Domain separation

Each key file's comment header records the domain-separation tag. The
sss codebase uses two distinct tags to prevent key-reuse-across-domains
(Pitfall 14):

- `sss-release-artifact-sig-v1` — release-artefact signing (this directory).
- `sss-envelope-sig-v1` — envelope-sig material (per-user keystore, Phase 19).

A key tagged for one domain MUST NOT be used in the other; a release
key MUST NOT appear in a user keystore and vice versa.
